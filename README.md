# レアバード・スコープ

羽田・成田（変更可）に **今日・明日、何時に、どの滑走路で** 撮る価値のある機体が発着するかを予報するページです。
GitHub が5分おきに自動で計算し、スマホで見られるページとして公開します。無料・メンテナンス不要で動きます。

- 特別塗装機の台帳（日本と海外の航空会社）は毎朝自動で追加・抹消
- 政府専用機・要人機・軍用機・珍しい機体も、公開データベース（約1.1万機分を使用）で毎日自動更新して見張る
- 羽田・成田とも公式サイトの時刻表と照合（貨物便は便名→経路データから）
- 経路の分からない機体は、機首の向きでは行き先を決めず、最終進入に入った時点で判定
- 滑走路は予報風（TAF・Open-Meteo）と公式の運用ルールから予測し、直近は実際に進入中の機体の向きで判定
- 国際線は相手国を出発した時点（10時間以上前）で「確定」。日本を出た機体は、翌日の折り返し便まで予測
- 前夜21時に翌日、朝6時に当日の予報。注目機は到着が確定した時点と約90分前にスマホへ通知（任意）
- 国内線に「ふつう入らない機材」（777-300ER・A350-1000 など）や、その空港に「ふつう来ない機材」（Q400・ATR など）が入った便を、出発地を飛び立った時点で見つけて表示・通知
- 国際線は、その便の過去の実績に無い機材が入ったら「普段と違う機材」として表示・通知
- 緊急信号（7700・7600・7500）を出している機体を画面の先頭に表示し、近ければ通知
- 出発便は、地上で信号を出し始めた時点（プッシュバック・エンジン始動後）で「出発準備中」として表示・通知
- 滑走路は「いまの運用」から出発し、追い風5ktを超える時間に切り替わると予測。風は METAR（いま）→ TAF（約30時間先まで）→ 気象庁MSM の順、撮影条件は気象庁の降水確率＋MSM＋TAF で判定
- 予報が間違っていたら、画面の「✓ 違う」か通知の「間違いを報告」を押すだけで、証拠と一緒に記録（Claude があとで調べて直す）

## 設置手順（初回だけ・15分ほど）

1. **GitHub のアカウントを作る**
   https://github.com/signup から登録します（無料）。

2. **リポジトリ（保管場所）を作る**
   右上の「＋」→「New repository」
   - Repository name: `rarebird`
   - **Public** を選ぶ（無料で自動実行とページ公開ができるのは Public です）
   - ほかはそのまま →「Create repository」

3. **ファイルを入れる**
   作成直後の画面にある「uploading an existing file」をクリック →
   このフォルダの `rarebird.py` `index.html` `config.json` `README.md` の4つをドラッグ＆ドロップ →「Commit changes」

4. **自動実行の設定ファイルを作る**
   「Add file」→「Create new file」
   - ファイル名の欄に `.github/workflows/rarebird.yml` と入力（`/` を打つとフォルダになります）
   - 本文に、同梱の `rarebird.yml` の中身をすべて貼り付け →「Commit changes」

5. **通知の合言葉を決める（通知が要らなければ飛ばしてOK）**
   「Settings」→「Secrets and variables」→「Actions」→「New repository secret」
   - Name: `NTFY_TOPIC`
   - Secret: 他人に推測されにくい英数字（例: `rarebird-k7m2-q9xa`）
   - 「Add secret」

6. **初回の実行**
   「Actions」タブ → 左の「rarebird」→ 右の「Run workflow」→ 緑の「Run workflow」
   1〜2分で緑のチェックが付けば成功です。

7. **ページを公開する**
   「Settings」→「Pages」→ Build and deployment の Source を「Deploy from a branch」、
   Branch を「site」「/ (root)」にして「Save」。
   数分後に `https://（あなたのユーザー名）.github.io/rarebird/` で見られます。
   スマホのホーム画面に追加しておくとアプリのように使えます。友人にはこのURLを送るだけで共有できます。

8. **スマホに通知を届ける（手順5をした場合）**
   「ntfy」アプリを入れる（Android: Google Play／iPhone: App Store）→「＋」→ 手順5の合言葉を入力して購読。

以後は何もしなくても5分おきに更新されます（GitHub の混雑で遅れることがあります）。

## 変えたいとき

GitHub 上で `config.json` を開き、右上の鉛筆アイコンで編集 →「Commit changes」。次の更新から反映されます。

| 項目 | 意味 | 例 |
|---|---|---|
| `airports` | 撮影拠点の空港（ICAOコード） | 関空 `RJBB`、伊丹 `RJOO`、中部 `RJGG`、新千歳 `RJCC`、福岡 `RJFF` |
| `extra_rare_types` | 希少機種に足す型式（ICAO型式コード） | `["B779", "A359"]` |
| `not_rare_types` | 希少機種から外す型式 | `["B77L"]`（777Fが多すぎる場合など） |
| `domestic_unusual_types` | 国内線を飛んでいたら注目する機材（国際線ではふつうの機材なので国内線に限る） | `["B77W", "A35K", ...]` |
| `airport_unusual_types` | その空港に発着したら注目する機材（空港ごと） | `{"RJTT": ["DH8D", "AT76", ...]}` |
| `pinned_regs` | 台帳と関係なく常に見張る機体 | `"JA123A": "メモ"` |
| `ignored_regs` | 見張らない機体 | `["JA999A"]` |
| `plane_alert` | 政府・要人機などのデータベースの使い方（下記） | |
| `notify` | 通知の時刻（時）と、接近通知を何分前から出すか・夜間停止の時間帯 | |

### 政府・要人機・軍用機・珍しい機体（`plane_alert`）

| 項目 | 意味 | 既定 |
|---|---|---|
| `enabled` | 使うかどうか | `true` |
| `groups` | 使うまとまり。`vip`＝政府・要人機、`mil`＝軍用機、`rare`＝珍しい機体（An-124・歴史機など）、`public`＝海保・警察・消防・国の業務機 | `["vip", "mil", "rare"]` |
| `extra_categories` / `exclude_categories` | データベースの分類名で個別に足す・外す | `[]` |
| `global_categories` | 世界中から探す分類（相手国を出た時点で確定させる） | 国家元首・政府・王室・特別機 |
| `regular_days` | 直近14日でこの日数以上来た機体は「よく来る機体」として自動で外す（`0`で無効） | `4` |

- 羽田には海上保安庁の基地があり毎日飛ぶため、`public` は既定で使いません。
- 個人・企業の自家用機、著名人の機体などの分類は、特定の人の移動を追うことになるため使いません。
- 国家元首機・政府機以外は、空港の150nm圏に入ってからの判定です（着陸の30〜40分前）。

羽田・成田以外の空港は公式時刻表を使えないため、観測実績と経路情報からの推定になります（1〜2週間で充実します）。
書式を間違えても止まらず、ページ上部に警告を出して既定値で動きます。

## 表示の見方

- **確定** … ADS-B で実際に飛行中（相手国を出発済み）・発着を確認した便。洋上で一時的に見えなくなっても到着予想時刻まで保持します
- **有力** … 時刻表と過去の機材実績、曜日パターンから確度が高い便
- **傾向** … 過去の実績からの推定。「来る確率」と「よく来る時間帯」を表示

特別塗装機がどの便に入るかは、航空会社が当日まで決めないことがあります（ANA 公式にも「当日まで決定いたしません」と明記）。
そのため **明日の特別塗装機は「来る確率と時間帯」までが限界** で、当日の朝に飛び始めると「確定・有力」に切り替わります。

## 誤りを見つけたとき

各便のカードの「✓ 違う」を押し、どう違ったか（来なかった・空港が違う など）を選ぶだけです。通知の「間違いを報告」ボタンでも同じです。
次の自動実行（5〜10分以内）で、そのときの記録・航跡・経路情報と一緒に `data/reports.json` に保存されます。
Claude に「報告を見て」と頼めば、この記録を読んで原因を調べ、修正します。

## うまく動かないとき

- ページ上部に警告が出ます（データ取得の失敗・更新の停止・設定の誤り）
- 「Actions」タブで赤い×が付いた実行をクリックするとログが見られます
- GitHub は60日間動きのないリポジトリの定期実行を止めますが、月1回自動で記録を残すので通常は止まりません

## データの出どころ

adsb.lol（ODbL）／ VRS standing-data（経路データ）／ Plane-Alert-DB（ODbL）／ 成田国際空港公式サイト（内部API）／ 羽田空港旅客ターミナル公式サイト（内部APIのため仕様変更で止まる可能性あり）／ aviationweather.gov（METAR・TAF）／ 気象庁（府県天気予報）／ Open-Meteo（気象庁MSM・汎用モデル）／ 特別塗装機一覧（viaflight-jp.com の日本版・世界版）／ OurAirports（パブリックドメイン）／ 地理院タイル。
運用中の滑走路は、実際に進入中・離陸直後の機体の向きから判定しています。
